# WebBlackbox Enterprise Administration

## Managed Extension Policy

Enterprise deployments can provide a managed policy object through `chrome.storage.managed` under `enterprisePolicy`. The extension declares `storage.managed_schema` (`managed-schema.json`, generated by the build), so the policy is visible and validated in `chrome://policy`. The same keys are also accepted at the top level of managed storage (the legacy flat layout); when both are set, the keys under `enterprisePolicy` win.

Top-level keys: `siteAllowlist`, `siteDenylist`, `dataCategoryCaps`, `disableLabMode`, `playerUrl`, `retention`, `profiles`, `rules`.

```json
{
  "enterprisePolicy": {
    "siteAllowlist": ["https://app.example.com", "*.trusted.example"],
    "siteDenylist": ["https://admin.example.com"],
    "dataCategoryCaps": {
      "screenshots": "off",
      "network": "metadata",
      "storage": "counts-only",
      "cdp": "off",
      "tabsContext": "metadata"
    },
    "disableLabMode": true,
    "playerUrl": "https://player.example.com/",
    "retention": {
      "localTtlMs": 86400000,
      "shareTtlMs": 604800000
    }
  }
}
```

`siteDenylist` wins over `siteAllowlist`. If `siteAllowlist` is non-empty, recording is denied outside the allowlist. `disableLabMode` caps `cdp` and `heapProfiles` to `off` and turns a `lab` capture policy into `private`. `dataCategoryCaps` accepts the categories `actions`, `inputs`, `dom`, `screenshots`, `screenRecordings`, `console`, `network`, `storage`, `indexedDb`, `cookies`, `cdp`, `heapProfiles` and `tabsContext`, with the same levels as a profile's categories. `dataCategoryCaps` are a ceiling for every recording profile, presets included; the popup names the capped categories and archives record them. If the policy changes what a running recording's profile may record, the recording is stopped as soon as the policy changes and the user is told why.

Capping `cdp` to `off` (directly, or through `disableLabMode` as in the example above) takes away the Full engine's data source: the debugger is never attached, so a Full recording gets no network, runtime errors or CDP screenshots, and the `webRequest` network baseline runs only for Lite recordings. Leave `cdp` uncapped and `disableLabMode` off if your users need the Full engine.

The policy is read when a recording starts, with a 3-second limit: Chrome can hold `storage.managed` back while a page opened at browser start is still loading, and a recording started in that window goes ahead without the policy (the service worker logs "enterprise policy not available yet"). Treat the policy as a guard rail rather than the only control.

### Player URL

`playerUrl` is the address of your organization's (self-hosted) Player. The extension has no built-in Player address: "Export and open in Player" on the Sessions page is hidden until a Player URL is set, either here or by the user in Options → Export & encryption. A managed value wins; Options shows it read-only with a "Set by your organization's policy" note. It must be an `https://` URL (`http://` only for `localhost` or `127.0.0.1`) without credentials; any other value is ignored. Only the page is opened after the export: the archive stays in the user's downloads folder and is opened in the Player locally, and neither the archive nor its passphrase is sent to this address.

### Managed Recording Profiles And Rules

The same policy object may ship read-only recording profiles and site rules. They appear to users as `managed:<id>` and cannot be edited or deleted, only duplicated. Users can delete the built-in presets; a rule that points at a deleted preset is skipped until the user restores the recommended profiles. Rules may point at managed profiles or at the built-in presets (`builtin:lite`, `builtin:full`, `builtin:qa`, `builtin:full-capture`). Rules never start recording; they only pick the profile.

```json
{
  "enterprisePolicy": {
    "rules": [
      {
        "id": "stage-qa",
        "name": "Stage environments",
        "profileId": "builtin:qa",
        "priority": 10,
        "enabled": true,
        "match": { "hosts": ["*.stage.example.com"] }
      }
    ]
  }
}
```

Profiles use the same JSON shape as the options page export (`Export JSON`). Only `id` and `name` are required: missing blocks and fields (`categories`, `redaction`, `network`, `pointer`, `sampling`, `recorder`, `export`, `base`, `unmaskSelectors`, `sitePolicies`) take the built-in defaults (those of an unedited `Default` profile), the optional `description`, `visual` and `localData` may be left out (a partial `localData` is completed with the defaults: delete after export, 10 minutes' retention), and a profile with an invalid value is skipped and reported on the options page. The managed schema does not declare every profile field: `sourceMaps` and the redaction fields `contentRedaction`, `builtInHeuristics`, `redactQueryParams`, `redactStorageKeys` and `valuePatterns` are missing, so check `chrome://policy` for schema errors after pasting an exported profile and don't count on those fields reaching the extension. A list you set replaces the default list instead of adding to it: a `redaction.blockedSelectors` without `input[type='password']` and the other default entries blocks only what you list.

## Self-Hosted Share Server

Recommended production settings:

```bash
WEBBLACKBOX_SHARE_BIND_HOST=127.0.0.1
WEBBLACKBOX_SHARE_ALLOWED_ORIGIN=https://player.example.com
WEBBLACKBOX_SHARE_API_KEYS="upload-v2:upload;reader-v2:read;ops-v2:list,revoke"
WEBBLACKBOX_SHARE_DEFAULT_TTL_MS=604800000
WEBBLACKBOX_SHARE_MAX_TTL_MS=2592000000
WEBBLACKBOX_SHARE_RETAIN_EXPIRED_MS=2592000000
```

Rotate share API keys by deploying old and new scoped keys together, moving clients to the new key, confirming audit activity, then removing the old key.

## Audit Logs

Local export audit events are stored under `webblackbox.audit.exports` in extension local storage. Share access audit events are written to `audit/share-access.jsonl` under the share data directory.

Audit entries are redacted and must not contain raw URLs, payloads, selectors, passphrases, API keys, or archive plaintext.

## Retention And Deletion

Use managed extension `retention` caps for local sessions and share server TTL settings for shared archives. `retention.localTtlMs` caps how long a stopped, unexported recording is kept (the shorter of it and the profile's retention); recordings never outlive the browser session either way. `retention.shareTtlMs` is only recorded in the archive's capture policy; the share server's TTL settings decide when shares expire. Revocation blocks share access immediately. Expired archives are pruned after the configured expired-retention window.
